# Tracks & Trade · 稳态经济设计

Sep 22, 2026 · @Someone

## 核心哲学：稳态经济

玩家不动手，引擎每回合的平均净收入就是一个常数 c。玩家的每一次购买都是把 c 从一个常数改成另一个常数，一次阶跃；除此之外没有任何东西会让 c 自己变。

由此推出三条：

1. **长期目标只有两件事**：扩大产能与需求，以及优化生产线上的瓶颈（产能、需求两层，任何一层卡住往另一层花钱都是浪费）。
2. **短期手段是点击脉冲**：手动点击在 c 之上叠一段临时收益，坐着点就有、走开就没，用来快速攒钱买下一次阶跃。点击收入进余额，不进定价均值。
3. **收益在消费发生，支出在生产发生**：城镇卖出时进钱，工人产一件扣工资。布局差的惩罚是利润薄、引擎慢，永远不是破产。

统一定价公式：任何一件让 c 变化的东西，价格 = Δc × 回本回合数 × 1.5ⁿ。板块是唯一例外，它不改 c，按地图大小指数定价，是整个游戏的主瓶颈。

验收的表现：任何一笔购买之后，顶栏「每回合收入」在有界的过渡期后跳到一个新的常数并停在那里，玩家看得见那一跳。

## 现有设计里已经服务于它的

大部分底座已经是对的，这些保留不动。

| 机制 | 服务的原则 |
| --- | --- |
| 整数件、1 tick = 1 回合、确定性种子、渲染与模拟分离 | c 能成为一个可算出的常数 |
| 价格固定按件，不随等级、供货量浮动 | 玩家不动手 c 不变 |
| 删掉随机事件、离线收益、浮动价格、自动升级 | 同上 |
| 产量只由工人数（≤3）和全局工艺决定；需求只由居民数（≤3）和时代决定 | 两层上限都是离散阶跃，每次购买 = Δc |
| 居民、工艺、时代按「新增收入 × 30 回合 × 1.5ⁿ」定价 | 已经是 Δc × 回本期 |
| 派货按下游价值排序、同价轮转 | 稳态分配确定 |
| 堆场 20 件封顶；加工厂预约量 = 5 回合缓冲 + 产能 × 路程 | 过渡期长度有界 |
| 城镇需求池最多攒 20 回合 | 吸收短脉冲，不改稳态 |
| 拆建全额退款 | 玩家敢改 c |
| 板块价随地图大小指数涨（2000 × 2.2^⌊(n−1)/2⌋） | 开图是唯一不属于 Δc 的目标 |
| 无死局三规则 | c ≥ 0 永远修得起第一条路 |
| 地图只画状态、不判瓶颈 | 玩家自己从账本和状态读瓶颈 |

## 现有设计里和它打架的

四处要改。道路无运力、无等级这一条不再是问题：路不参与经济，玩法专注在建筑供需上（见新增机制）。

| 现状（v0.12/0.13 文档） | 问题 | 改法 |
| --- | --- | --- |
| 建筑 = max(底价, 当前收入 × 2)，道路 = max(250, 当前收入) | 价格跟着 c 涨：同一座建筑晚建比早建贵，拆了重建也贵，和全额退款、「敢拆」冲突；最优策略变成囤 | 建筑和路只按同类第几座 × 1.3ⁿ⁻¹ 涨，不挂收入 |
| 定价用「近 30 回合收入均值」，点击收入和需求池爆发式售出都算在内 | 猛点一阵反而把下一件东西点贵；积压后的集中售出抬高均值 | 定价均值只算自动收入；或直接用解析算出的稳态 c |
| 没有任何持续成本 | 「布局差收益低」目前根本不成立，积压的货没有代价 | 见成本模型 |
| 时代只做倍率 | 稳定的 c 永远不需要主动拆掉重建，全额退款没有用武之地 | 高时代城镇停收低级货，留到下一版但要进路线图 |

文档内部的自相矛盾，一起清掉：

- 板块定价有三套：正文 2000 × 2.2^⌊(n−1)/2⌋；定价表「F5 之后 max(2500, 收入 × 10)」；教学表 F1 = 500。
- 第九节经济模型仍按车位、运费、驿站那一版写，与第七节「路无运力」对不上。删掉第九节里的运力、运费、驿站，按工资模型重算。
- 标题写 v0.12，沿革表已到 v0.13。

## 新增机制

### 道路的定位：一次性造价，不参与经济

每段路只有一次性造价（250 × 地形系数），没有运力、没有运费、没有等级、不能升级。一件货每回合走一段只是延迟，稳态吞吐与路无关。路存在的全部意义是「谁和谁连着」，玩家在路上的决策只有两个：修不修、走哪边（距离 × 地形的造价）。

试玩结论：运力和运费让经济模型难算，玩家也读不出路是不是瓶颈。瓶颈只可能出现在建筑和城镇上，地图上要读的状态只有堆场满、缺输入、收不下了三种，路上永远没有状态。

### 成本模型：支出在生产发生

| 支出 | 何时扣 | 上界 |
| --- | --- | --- |
| 工资 | 工人（或点击）每产一件扣 w | 堆场满 20 停工，工资随之停 |
| 建筑、路、工人、居民、科技、板块 | 购买时一次性 | — |

没有按回合扣的固定费，没有维护费。走开一小时回来引擎不会烧钱。

一条链每件净赚 = 售价 − 各环节工资之和，每回合净收入 c = Σ 件数 × 每件净赚。差布局的表现是 c 薄（工资高的环节喂了低价买家），不是 c 负。

### 余额地板为 0

余额永远不低于 0，生产线照动，扣不到的支出记为「减免」。账本不变量改为：余额 = 开局 + 卖货收入 − 支出 + 退款 + 减免，减免单独一栏，测试可查。慈善只在余额层面：亏本链在城镇面板照样显示负的每件净赚并标琥珀，玩家看得见。

### 派货按净值

派货优先级里的「下游价值」改为净值（售价 − 工资）；净值 ≤ 0 的需求不派。稳态下引擎永远非负，负余额只出现在货在路上、钱没回来的过渡期。城镇连着路却没人送时，面板写一句「运到这里不划算」。

### 稳态收入显示

顶栏两个数：解析算出的稳态 c，和近 30 回合实际。两者的差就是过渡期或点击脉冲。购买后玩家看到 c 跳到新常数，这就是那笔钱买到的东西。

### 利润账本进城镇面板

每条链一行：售价、工资、每件净赚、每回合件数、应收 / 实收、在途 n 件。「应收 / 实收」把「上游产不够」和「还在路上」区分开。

### 飘字

建筑生产时飘 −w（工资真的在这里花），城镇卖出时飘净额 +y。堆满停工时建筑不动也不飘。不在建筑上飘钱以外的东西，不飘毛收入。

### 生成器的距离承诺

城镇按到最近原料地的固有距离 d 定价（d 封顶 5）。生成器承诺永远不打破它：新花放下时，任何能产这座城镇所收货物的原料格，到该城镇的可通行路程 ≥ d − 1，朝向打分里一票否决。价格固定、地图回应局势、「远」始终是地图给的属性，三件事同时成立。

奖励挂地理，成本挂造价：远城镇价高是探索的诱因，绕路只多付一次性的造价。连路本身不需要「远近取舍」——近的资源点会因为一格一座、每座 3 人先被榨干，玩家自然去连远的。

### 板块调大、密度调低

路不参与经济之后，画路的乐趣只剩「放哪、绕哪」，这需要连片的空地。现在七格花两三格山湖再加一座城镇或原料，剩下的草地经常连一条路都要绕，所以先把空间放出来。

板块改为 19 格大花（中心加两圈），同样能无缝铺满六边形平面，生成器只改花心格点和朝向打分，其余约束照搬。备选是保持 7 格花但把原料砍到每两朵一格、城镇每三四朵一座，改动小但空地仍是零碎的；路的取舍需要连片空地，所以选 19 格。

连带三处：

- 开局金币要装得下更长的第一条路，无死局守卫的 firstRoad 按新地图重算。
- 板块价按面积重新标定，19 格一档的价格约等于原来两块 7 格的价格。

## 扩容系统：三档 × 两层

扩容不杂，它是一个对称结构：产能和需求两层各有局部、全局、空间三档，档位不同的是尺度和价格曲线，不是概念。玩家任何时候面对的只有两个动作——「点这个节点」或「去科技树」。运力不是一层：路不参与经济。

| 层 | 局部（封顶 3，线性涨价） | 全局（无限轴，按新增收入定价） | 空间（要开图） |
| --- | --- | --- | --- |
| 产能 | 建筑雇工人 | 该类建筑的工艺 | 新建筑 |
| 需求 | 城镇加居民 | 时代 | 新城镇 |

设计规则：

1. 每一档在游戏的某个阶段必须有一段「它最便宜」的窗口，选择顺着价格曲线自然滚过去，玩家不需要同时比较六个按钮。
2. 局部档先便宜后封顶，封顶把玩家推向全局或空间；全局档随规模涨价，晚期才划算；空间档被板块价卡住，是长期目标。
3. 运力不设升级。路只有一次性造价，逐段扩容是微操，全局车队又让经济难算、瓶颈难读，试玩两者都否了。物流的复杂度全部折进「建筑放哪」——双输入配方的两条来路汇到哪、加工厂离几座上游多远。
4. 界面上每个节点只露一个扩容按钮（建筑 = 雇第 n 名工人，城镇 = 加第 n 名居民，满 3 消失），全局两张卡都放科技树。六档不会同时摆在玩家眼前。
5. 金手指是产能层的手动档：一次点击 = 这座建筑上 k 名工人干一回合的活，k 随等级涨，其余规则和工人生产完全一样——扣工资、受堆场和输入库存约束、进当回合统计。不改堆场、不改需求池、不改任何别的属性。点错建筑（堆场已满或缺输入）没反应，点对瓶颈哗一下流走，地图自己告诉玩家点哪；不需要冷却，堆场和下游需求就是上限。

验证：用第九节的最优玩家脚本跑一遍，统计六档各被选中几次。有一档从来不被选，就砍掉或改它的价格曲线；最可疑的是工艺——早期工人少时便宜但收益小，晚期收益大但价格也大，可能一直夹在「再雇一个」和「开图」之间。

## 参考游戏怎么做的

共同点：不让玩家操作运输，但让「连不连、连哪条、先连哪条」这个决定变稀缺、变有代价。

| 游戏 | 借来的 | 不借的 |
| --- | --- | --- |
| [Mini Motorways](https://www.pockettactics.com/mini-motorways/review) | 只有画路和拆路两个操作；路块有限；升级（高速、环岛、桥）全局给、每周二选一；商店门口堆 pin 就是瓶颈信号；只控制基础设施不控制车辆反而更有深度 | 失败条件、限时 |
| [Age of Steam](https://www.meeplemountain.com/reviews/age-of-steam/) / [Railways of the World](https://www.rpg.net/reviews/archive/14/14640.phtml) | 每回合最多铺 3 段、断头路不接就作废（稀缺）；火车头等级是第三层瓶颈 | 按走过的段数付钱——地图固定、轨道稀缺时成立，地图会长、钱无上限时就是鼓励绕路 |
| Brass: Birmingham | 连上就「够得着」，货不逐段走；有些原料沿网络流、有些不用，拓扑决定哪条产线能开工；铁路时代修一段路消耗一份煤（修路和卖货争同一份货）；时代切换拆运河逼重连 | 多人抢位、共用他人路网 |
| [Station to Station](https://indiegames.substack.com/p/puzzles-on-rails-station-to-station) | 轨道不能交叉、铺了不能拆，深度全靠提前规划；车站四个固定朝向 | 关卡制、不可拆（和全额退款冲突） |
| Roads & Boats | 路便宜、车（驴）稀缺且要分配到线路上；局部资源必须运输才能到别处 | 手动车辆、船只 |

对本作的结论：路只负责连通、不参与经济（Brass 的「连上就够得着」），远送溢价挂地理而非路径（避开 Age of Steam 的绕路），拓扑的取舍来自建筑放哪、多输入配方往哪汇（Brass 的辐射范围），时代切换作为唯一逼玩家重建引擎的机制（Brass）。Mini Motorways 和 Roads & Boats 的运力/车辆那一层试过，经济难算、瓶颈难读，不借。

## 哲学不允许的东西

下一版再想加这些时先回来看这一节。判据只有一条：它会不会让玩家没动手的时候 c 自己变。

- 随机事件、天气、灾害、市场波动
- 资源枯竭、建筑老化、任何随时间衰减的量
- 按回合扣的维护费、固定开销，任何让引擎挂着就烧钱的东西
- 价格随供货量、全图数量、连接段数浮动
- 城镇自动升级、需求自动增长
- 离线收益、追赶墙钟时间
- 按实际路程加价的卖价（奖励绕路）
- 价格挂当前收入（惩罚晚建和重建）
- 道路参与经济：运力、运费、等级、逐段升级、手动车辆
- 系统判定瓶颈并给结论

允许的例外：点击脉冲（玩家肉体劳动，走开就没）；时代切换改变城镇收购清单（玩家自己买的阶跃）。

## 验收标准与测试

验收的是玩家能不能读出账，不是数字上涨。

- [ ] 任何购买之后，稳态 c 在有界过渡期（≤ 最长路程 + 20 回合）后跳到新常数并停住
- [ ] 解析算出的 c = 引擎跑 200 回合的均值，对每条链、每种配方、每种路程各写一个用例
- [ ] 只点击不买东西，定价均值不变
- [ ] 一条净值 ≤ 0 的链永远不派货；派货改为净值排序后，任何稳态的减免为 0
- [ ] 余额永不为负；减免只在过渡期出现且有界
- [ ] 拆路后已在路上的货落地为当地库存，不销毁、不瞬移
- [ ] 生成器一千个种子：新原料到已定价城镇的路程 ≥ d − 1；下游缺口仍能在两块内闭合
- [ ] 建筑和路的价格与当前收入无关；拆了重建同价
- [ ] 玩家能指出任何一件货现在在哪、为什么还没卖掉、这条链每件赚多少
- [ ] 同一个瓶颈至少有两种解法（加工人 / 再建一座 / 就近加工 / 加居民 / 升时代 / 开新城镇），玩家会比较
