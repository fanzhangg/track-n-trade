# v0.11 设计定稿：点击生产与工人

定稿日期：2026-09-21。在 v0.10 的整数模型上加入 Cookie Clicker 式的点击体验：建筑不会自己生产，玩家点击建筑才出一件货；买了工人，建筑才开始每回合自动生产。物流永远自动，体验保持简单。

## 为什么改

v0.10 里玩家落地一座建筑就能坐着看它自动产货，前十分钟没有手上的事做，只有「钱够了没」。点击把节奏交回玩家：开局每一件货都是自己点出来的，第一名工人是用点出来的钱买的，之后每一次扩张都是"把手上的活交给工人"。

## 三件事决定产量

| 来源 | 每次/每回合产出 |
|---|---|
| 一次点击 | `1 + 工具改良等级` 件 |
| 一名工人 | `1 + 工人培训等级` 件/回合 |
| 建筑本身 | 0 |

建筑类型、地形、设备都不再影响产量。**影响一座建筑产量的只有它的工人数**，工人本身的效率是全局科技。地形只决定道路造价。

**每座建筑最多 3 名工人。** 这个上限是有意的：它把纵向堆叠的路封死，产量到顶之后只剩两条出路，开新建筑或买工人培训，前者逼玩家往地图外走、去处理更长的路线和新的城镇，后者是唯一的无限轴。上限是 3 还让工人可以画成三个固定槽位，一眼数得清。

点击受堆场约束：堆满 20 件时点击被拒绝，锯木厂门口没有原木时点击被拒绝。错误提示每秒最多弹一次，连点不会刷屏。

点击产出记在当回合的统计样本里，所以面板上的"近 30 回合实际"同时包含手点和工人的量。倍速只压缩回合长度，不影响点击。

## 定价

| 项目 | 价格 |
|---|---|
| 新建筑 | 伐木营 1200 · 锯木厂 2400 · 采石场 1600 |
| 同一建筑第 n 名工人（最多 3 名） | 伐木营 400 / 采石场 600 / 锯木厂 1000，每多一名 ×1.3 |
| 工人培训 Lv n | 5000 × 2ⁿ |
| 工具改良 Lv n | 2000 × 2ⁿ |
| 道路每段 | 250 × 地形系数（1 / 2 / 3），桥 ×3 |
| 道路扩容 | 该段造价 ×3 |
| 城镇扩建 | 1500 × 1.5^L |
| 货运马车 | 16000 |

第一名伐木工 400 金币 = 20 根原木卖进西镇，正好是开局点 20 下的量，和 Cookie Clicker 开局点十几下买第一个 cursor 是同一个节奏。

## 卖货侧翻倍

点击的节奏比 v0.10 的自动生产快得多，城镇和道路按 v0.10 的数值会立刻堵死，所以两层都翻倍：

| 项目 | v0.10 | v0.11 |
|---|---|---|
| 城镇每级每回合收 | 1 件 | 2 件 |
| 普通道路每回合放行 | 2 件 | 4 件 |
| 扩容道路每回合放行 | 6 件 | 12 件 |

一名工人喂不满一座一级城镇的一种货，所以前期一直有「再雇一个还是先修路」的选择；一座满编建筑（3 件/回合）刚好压过一级城镇、还填不满一条普通路（4 件/回合）；同一条路上挂到第二座满编建筑，路就成了瓶颈。扩路、扩城、开新城镇三条路重新变成三选一，v0.10 的三层张力保留。

## 开局：一座伐木营

地图上只有三座城镇和一座伐木营（`-2,1`，西镇隔壁的森林），没有道路，1000 金币。锯木厂、采石场、道路、工人全部由玩家自己摸索，里程碑给方向：

点第一下 → 卖进第一座城镇 → 雇第一名工人 → 建成采石场 → 建成锯木厂 → 扩容道路 → 扩建城镇 → 架桥 → 把一座建筑的工人雇满 → 第一次工人培训 → 三座城镇 → 收入门槛。

目标条在点第一下之前只说「点击伐木营」；点过之后换成「原木堆在门口卖不掉，把伐木营拖到西镇修路」。

## 删掉的东西

- **高效设备**：和「只有工人数影响产量」冲突，改由工人培训承担。
- **蒸汽锯**：同上，锯木厂不再有专属倍率。
- **密林 / 富岩地 ×2**：地形只影响道路造价。
- **暂停生产按钮**：没有工人的建筑本来就不产货，辞退工人即可。
- **建筑模块**：改名为工人，第一名不再随建筑附送。

## 工人的画法：Cookie Clicker 的 cursor

地图格子上不写「工人 n · n 件/回合」这种字，改成一排手指，就是 Cookie Clicker 里围着饼干点的那种光标。一名工人一只手指，没雇的槽位不画占位符。

**界面上看不出产能上限。** 不画空槽位，侧栏也不写「n / 3」，满员时「雇工人」按钮直接消失。上限是设计上的结构约束，不是玩家需要盯着的数字；让它留在界面上只会多一层认知负担，还会把注意力从「下一步该扩哪里」引到「这个格子还差几个」。

**每只手指按自己的节拍朝建筑点一下。** 一个回合里 n 名工人的节拍均匀错开（第 i 名延迟 `i/n × 节拍`），所以一名工人两秒点一下，三名工人两秒点三下：工人越多，看到的动作越密。这就是把速率画出来的办法，静态的数量只能表示规模。工人培训不加槽位，它缩短节拍（`节拍 = 回合时长 ÷ 速度 ÷ 工人效率`，下限 0.25 秒），格子上补一个「×n」。

这是一段抽象的节拍，不是对工人真实动作的模拟：引擎里所有工人在回合边界同一瞬间出货。允许这个抽象的前提是它在一件事上绝不撒谎——**建筑停工的时候动画必须停**。堆场满了、锯木厂缺原木、玩家暂停游戏，手指就停下来。停的时候是整个去掉动画（`animation:none`）而不是暂停它，所以手指一定回到静止位置，不会冻在半空看着像卡住了；同时颜色转成灰色。不动了就是出问题了，不用读字。

手指用 Kenney Cursor Pack 的 `hand_point_n`（描边版，32×32，CC0），和全套界面图标同源。它指向正上方，恰好对应向上扑的动作。

实现上动画是纯 CSS，跑在合成层的 60fps 上，不占 JS 每帧开销。地图上的工人放在一个独立的 `<g class="tile-crew">` 里，只有工人数、堵塞状态或节拍变化时才重建，所以每秒十次的重绘不会打断动画。侧栏里是同一批手指、同一套节拍，靠负的 `animation-delay` 对齐相位，所以每次重建面板也不跳帧。

## 界面其余部分

- 点地图上的建筑 = 生产一件并选中；点城镇只选中。按住拖动仍然是连路，6 像素阈值区分点击和拖动。
- 点击时格子弹一下，飘出一个「+n」。工人的每回合产量也飘「+n」，两者互不覆盖。
- 侧栏第一个动作是「雇第 n 名工人」并标出价格，满员时它消失。「手工生产」降为次级按钮。还没有工人时，光标那一行写「还没有工人，先手工生产攒钱」。
- 工人培训和工具改良与货运马车并排放在工具栏的科技区，一直可见。
